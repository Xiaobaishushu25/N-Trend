# 交易数据同步

柜台连接仍由 CTP API 维持。委托与成交回报触发合并查询；资金与完整持仓通过一个查询线程串行获取。前端刷新和推送订阅均不发起柜台查询。

链路：CTP → Python 内存快照 → 本机 SSE `/events` → n-headless → 已有认证 WebSocket 的 `trader.updated` → Tauri 界面。没有连接 n-headless 时，Tauri 可直接订阅本机桥接的 SSE。`/snapshot` 和 `/api/v1/trader/snapshot` 用于首次加载与重连补全。

Python 的配置 JSON 可额外设置：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `QueryIntervalSeconds` | 1.5 | 全部柜台查询共享的最小发送间隔，最小 1.5 秒；需满足实际柜台要求 |
| `ReconcileSeconds` | 30 | 周期校准间隔，最小 10 秒；独立于客户端数量 |
| `QueryTimeoutSeconds` | 15 | 响应超时告警阈值，最小 5 秒 |

初始化时持仓、资金、委托和成交四类查询均成功完成才标记 READY。持仓查询先积累临时结果，在最后一条成功回报后原子替换；空结果会清空持仓，失败则保留最后成功快照。查询发送失败与响应错误会排队重试。兼容参数 `force` 不绕过限频。

超时并不能证明柜台查询已经结束，因此超时后不释放在途查询槽位：界面标记未就绪，等最后响应或 CTP 重连后恢复。持续无响应时需排查连接或重启桥接服务，避免继续叠加查询。CTP 重连复用同一查询线程并重新初始化。查询失败会阻止使用未就绪数据报单，但只要交易连接已登录并确认结算，已有委托仍允许撤单。

SSE 每次连接先发送完整快照，之后在变化时发送，并每 15 秒补一份快照作为保活。n-headless 合并变化后向客户端转发完整快照，静默期间每 15 秒发送 `trader.heartbeat`。客户端正常接收时不定时读取 HTTP；超过 45 秒未收到推送时，最多每 15 秒读取一次缓存快照恢复。

界面资金展示柜台确认值和成功同步时间。服务端将实际持仓合约加入现有行情批次，额外合约行情仅用于展示，不进入启用品种的图表聚合和策略扫描。持仓浮盈仅在最近 15 秒接收到同一实际合约的有效行情、已知合约乘数、有效持仓成本、且同步未在进行时估算，并标注“估算”。主连行情不能替代实际持仓合约；条件不满足时展示“柜台”快照值。估算不改变权益、可用资金或交易风控输入。当前乘数来自已有品种表，新增品种应核对并更新。

验证（不连接柜台）：

```powershell

node --test tests/liveTrader.test.cjs
```

## 自动交易执行

预警仍由原分析模块产生。自动/手动扫描把新预警注册到执行引擎，后台也会补充数据库中尚未注册的有效待触发预警；通知是否开启不影响执行。主连只用于既有分析和解析实际交易合约。执行使用天勤实际合约盘口、合约最小价位和涨跌停价格，不使用主连价格报单，也不依赖 SimNow 原生条件单。

天勤桥接新增 `/api/execution-events` 长等待接口，按到达顺序保存实际合约行情更新。引擎逐条判断触价，再使用批次中最新盘口报单；短暂穿越不会因只保留最后一个价格而丢失。行情缓存跳号时，已有任务终止补仓并进入保护性退出；无法获取有效执行行情时不以旧价继续报单。

执行状态保存在服务端数据目录的 `trader_execution.json`，持有独占文件锁防止同一目录多个执行进程同时交易。预警 ID、任务状态、报单标识、实际成交去重键和未完成退出任务均会恢复。状态文件损坏或不能持久化时禁止新报单，不静默新建一套任务。

- 同一预警只创建一个入场任务；重新穿越价格不会重置任务。剩余补单量为目标量减去真实累计成交量，并等待此前委托结束、已报告成交全部收到后才重报。
- 重启后先核对已收盘 K 线与预警有效期，完成前禁止该品种新开仓；已有持仓的退出不受此门槛阻塞。数据库中过期的待触发预警不会重新注册。
- HTTP 提交成功不等于成交。只有柜台成交回报/成交查询才能创建、增减托管持仓，均价和 1R 风险也基于实际成交。委托结束不等于持仓已平掉，历史流水只记录实际平仓成交。
- Python 在报单前持久化委托标识和参数，重复 HTTP 请求不会重复提交。超时保留“结果未知”，通过私有流恢复和完整委托/成交快照核实；无法确认是否提交的任务不盲目重报。
- 半自动仅开仓需要确认，真实托管仓位的退出自动执行。仅监控模式不创建模拟持仓、不发送交易指令。
- 止损触发后退出任务持续有效，价格反弹不会重新开仓。部分开仓先撤掉剩余开仓委托，处理撤单期间新增成交，再对真实待平数量提交退出委托。
- 委托需要更积极价格时自动撤单，等待柜台终态及迟到成交，再按剩余量和最新盘口重报。没有改善价格时保留原排队委托；跌停没有对手盘时不会无意义地反复撤单。
- 全部执行任务共享至少 2 秒的报撤单间隔，退出任务优先于新开仓。上期所/能源中心平今、平昨由最新柜台持仓决定，混合持仓分批退出；成交后持仓尚未同步时保留退出任务等待查询完成。
- 已存在的手工柜台持仓不会自动冒充策略持仓。柜台持仓低于已确认的托管持仓时停止新报单并显示核对错误，不猜测外部操作属于哪个策略。

执行配置新增可选字段（旧配置自动使用默认值）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `order_wait_seconds` | 3 | 改价/重复撤单等待时间，最小 2 秒 |
| `slippage_ticks` | 2 | 首次委托相对对手价的积极价位数 |
| `max_slippage_ticks` | 20 | 开仓相对计划入场价的最大不利滑点 |
| `max_exit_slippage_ticks` | 0 | 退出滑点上限；0 表示在交易所价格限制内持续追价，设为正数则限制滑点，但可能暂时无法成交 |

断线、休市、无对手盘或提交结果仍未知时，任务保留真实未完成状态；全自动处理不能保证立即成交。只有有明确柜台依据时才恢复后续报单。

本轮执行改造仅保留三个核心回归场景，合并覆盖重启去重/未知提交、半自动止损追价/部分成交、部分开仓止损时的撤单竞态：

```powershell
cargo test -p n-core trader::execution::tests --offline --lib
```
