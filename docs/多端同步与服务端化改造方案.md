# ntrend 服务端化、多端同步与 Android 改造方案

## 一、总体方案

将现有架构调整为：

```text
天勤 Python Bridge
        │ 仅监听 127.0.0.1
        ▼
阿里云 ntrend-server
├── n-core 分析与扫描
├── SQLite 权威数据库
├── 定时刷新与实时行情
├── HTTPS REST API
├── WSS 实时事件
└── 数据库一致性备份接口
        │
        ├───────────────┐
        ▼               ▼
Windows Tauri       Android Tauri
├── 无业务数据库     ├── 无业务数据库
├── Rust 网络代理    ├── Rust 网络代理
├── 内存K线缓存      ├── 内存K线缓存
├── 本机UI配置       └── 本机UI配置
└── 每日拉取备份
```

最终只有服务端数据库是权威数据源。PC 与 Android 共享品种、分组、排序、信号、画线、批注、决策、复盘和服务端策略设置。客户端不保留纯本地模式，也不支持重启后的离线历史查看。

## 二、服务端改造

### 2.1 服务进程

保留现有 `n-headless` 包和二进制名称，避免破坏阿里云现有部署；将其扩展为完整服务端，内部拆分为：

- `runtime`：调度器、实时行情、天勤闭合事件、邮件、扫描。
- `api`：Axum REST API。
- `realtime`：WebSocket 连接、订阅与广播。
- `auth`：设备注册、令牌校验与吊销。
- `backup`：SQLite 一致性快照。
- `state`：服务状态、更新时间、事件序号和数据版本。

把目前位于 Tauri 壳中的 `spawn_scheduler`、`spawn_quote_poller`、天勤闭合事件消费、邮件触发和手动画线监控迁入服务端。客户端不再运行这些任务。

服务端必须保持单实例运行；启动时获取数据目录锁，拿不到锁就直接退出，防止两个进程同时刷新、扫描和写库。

### 2.2 数据库与同步状态

继续使用 SQLite + SeaORM，个人使用无需立即迁移 PostgreSQL。启用 WAL、busy timeout 和外键。

保留并迁移现有全部业务表，新增：

- `devices`
  - `id`、设备名称、令牌哈希、权限、创建时间、最后访问时间、吊销时间。
- `notification_history`
  - 将目前仅存在内存中的通知历史持久化并跨端同步。
- `sync_revisions`
  - 按 `symbols/groups/manual_levels/signals/settings` 等作用域维护递增版本。
- `idempotency_requests`
  - 保存客户端 mutation 的 `request_id`，防止网络抖动导致重复建组、重复画线或重复批注。

个人单用户模式不增加 `users` 表，也不在现有业务表增加 `user_id`。所有已注册设备共享同一套数据。

并发冲突采用简单规则：

- 所有写操作由服务端事务串行确认。
- 后提交成功的修改覆盖先前值。
- 分组和品种排序必须整组事务更新。
- 写入成功后广播 `state.changed(scope, revision)`。
- 其他客户端收到后重新获取对应作用域。
- 客户端离线期间不允许编辑，也不排队离线写入。

### 2.3 配置拆分

服务端配置采用“启动引导配置 + 可管理配置 + 服务端秘密”三层结构。

启动引导配置只允许在服务器上维护：

- 数据目录、数据库路径和服务监听地址。
- Caddy、域名、证书、systemd 与 Python 运行环境。
- 首次设备绑定使用的 `NTREND_ADMIN_KEY`。
- 这些配置不开放远程编辑，避免错误配置导致 API 无法启动、域名失联或管理设备被锁在服务外。

PC 主设备可在设置页面管理的服务端配置：

- 调度周期、抓取参数、数据源、天勤账号、SMTP、扫描逻辑、通知阈值、预检测配置和日志级别。
- 品种抓取、行情轮询、回填深度、交易时段限制和策略逻辑版本。
- 邮件收件人、发件人及通知开关。
- 普通设备的查看、吊销和权限调整。
- 非秘密配置保存在服务端数据库的 `server_settings` 表中，使其随数据库一起备份。
- 天勤密码、SMTP 密码等秘密保存在服务器 root-only 秘密文件中，使用临时文件写入、`fsync` 和原子重命名，权限固定为 `0600`。
- API 读取时必须隐藏天勤密码、SMTP 密码和管理密钥。
- 密码字段采用“留空表示不修改”的写入语义。
- 天勤和 SMTP 凭据永远不下发客户端。

配置生效分级：

- **立即热更新**：调度周期、扫描周期、抓取限速、通知阈值、预检测、邮件开关和策略业务参数。
- **保存后重建子组件**：天勤账号、天勤密码、bridge 端口和数据源切换；服务端只重启 Python bridge 并重新健康检查，不重启整个 Rust 服务。
- **保存后服务重启**：日志初始化等无法安全热切换的配置。页面明确显示“需要重启”，由 PC 主设备确认后触发受控重启。
- **仅服务器修改**：监听地址、数据目录、域名、Caddy、systemd、Python 可执行文件和管理密钥。

配置更新流程：

1. PC 提交时携带当前 `configRevision`，服务端拒绝覆盖过期版本。
2. 服务端完成字段范围、地址格式和配置组合校验。
3. 涉及天勤凭据时先写入临时配置并尝试启动、探活新 bridge。
4. 探活成功后才提交为正式配置；失败时恢复旧配置并重新拉起旧 bridge。
5. 普通配置在数据库事务中保存，并增加 `settings` revision。
6. 服务端返回各字段的 `applied`、`restart_required` 或 `rejected` 状态。
7. 配置变更写入审计日志，但秘密字段只记录“已修改”，不记录值。

PC 设置页提供“重启天勤桥接”和“安全重启服务”按钮。安全重启服务不允许执行任意命令：服务端进入维护状态、拒绝新 mutation、等待当前数据库事务结束、关闭 WebSocket、停止 sidecar 后主动退出，由 systemd 的 `Restart=always` 重新拉起。按钮需二次确认并设置 60 秒冷却时间。

客户端本机配置：

- API 地址、设备 ID、界面主题和布局。
- K 线显示根数、间距、右侧留白。
- 最后打开页面/分组。
- 本机是否显示系统通知。
- PC 备份目录、最后成功备份日期。
- 不参与多端同步。

服务端策略设置与本机界面设置在设置页中明确分栏，避免用户误以为手机修改窗口布局会影响 PC。

### 2.4 设备认证

采用个人使用的设备令牌方案：

1. 服务端环境变量保存一次性管理密钥 `NTREND_ADMIN_KEY`。
2. 新设备首次绑定时输入服务地址、设备名和管理密钥。
3. `POST /api/v1/devices/register` 返回只展示一次的长随机设备令牌。
4. 服务端只保存令牌哈希。
5. Windows 使用 DPAPI/Credential Manager 保存令牌。
6. Android 使用 Keystore 保存令牌。
7. Vue/JavaScript 永远拿不到明文令牌，所有请求由 Tauri Rust 层添加认证头。
8. PC 设置页可以查看设备列表并吊销设备。

权限分为：

- 普通 PC/Android：读写品种、分组、画线、批注和决策等日常业务数据，只读服务端配置。
- PC 主设备：额外具有 `settings:write`、`service:restart`、`bridge:restart`、`backup:read` 和设备管理权限。
- Android 不允许下载完整数据库备份。

客户端不自动重试写操作。写请求如果失去响应，先重新读取服务端状态；创建型请求携带 UUID `request_id`，服务端幂等返回原结果。

### 2.5 REST API

统一前缀 `/api/v1`，错误结构固定为：

```json
{
  "code": "ERROR_CODE",
  "message": "可展示信息",
  "requestId": "..."
}
```

核心接口：

- `GET /meta`
  - API 版本、服务版本、最低客户端版本、服务器时间。
- `GET /status`
  - 天勤状态、数据库状态、最后刷新、最后扫描和行情延迟。
- `/symbols`、`/groups`
  - 品种、关注状态、分组和排序 CRUD。
- `/klines/{symbol}/{timeframe}`
  - 初始、增量和向前分页查询。
- `/quotes`
  - 当前服务端行情快照。
- `/signals`、`/preclose`、`/review`
  - 信号、复盘、模型与预测数据。
- `/manual-levels`
  - 手动画线和触发记录 CRUD。
- `/annotations`、`/decisions`
  - 信号批注和交易决策。
- `/settings/server`
  - 服务端设置读取与更新，返回值必须脱敏，并返回配置 revision 与生效状态。
- `/admin/runtime/restart`
  - PC 主设备触发受控服务重启；只允许固定动作，不接收 shell 命令或进程参数。
- `/admin/bridge/restart`
  - 单独重启天勤 Python bridge 并返回健康检查结果。
- `/actions/refresh`、`/actions/scan`
  - 手动刷新和扫描。
- `/integrity`
  - 数据完整性查看和修复。
- `GET /admin/database-backup`
  - PC 主设备下载一致性数据库备份。

服务端返回 `apiVersion`，客户端启动时访问 `/meta`。服务端版本低于客户端要求或客户端低于服务端最低版本时停止业务请求，并显示明确的升级提示，不尝试兼容未知结构。

### 2.6 K 线接口与缓存协议

初次打开：

```http
GET /api/v1/klines/RB0/15m?limit=1200
```

响应：

```json
{
  "symbol": "RB0",
  "timeframe": "15m",
  "bars": [],
  "latestClosedTs": 1790301600000,
  "seriesRevision": 18342,
  "serverTime": 1790301612000,
  "hasMore": true,
  "nextBefore": 1789000000000
}
```

规则：

- HTTP 历史接口只返回服务端确认的已收盘 K 线。
- 时间使用 Unix 毫秒，同时服务端内部保留交易日语义。
- 客户端增量更新时从最后已确认时间向前重叠 2～5 根，再按时间戳 upsert。
- 左拖到历史边界时使用 `before` 分页加载，不一次返回全部历史。
- 单次默认 1200 根，最大限制 5000 根。
- `seriesRevision` 按品种和周期递增。
- 数据回补、换月映射或算法版本使历史大范围变化时，返回 `fullReloadRequired=true`。
- 高周期聚合由服务端统一生成，客户端不自行从 5m 聚合。

服务端数据库中的 5m 原始数据是权威数据；派生周期继续复用当前 `n-core` 逻辑。

### 2.7 WebSocket 实时协议

使用一个认证后的 WSS 连接，事件包含递增 `eventSeq`：

- `quote.updated`
- `kline.partial`
- `kline.closed`
- `data.updated`
- `scan.completed`
- `entry.triggered`
- `manual_level.triggered`
- `notification.created`
- `state.changed`
- `server.status`

客户端进入图表时发送订阅：

```json
{
  "type": "subscribe",
  "symbols": ["RB0"],
  "timeframes": ["15m"]
}
```

服务端推送完整的进行中 K 线快照，而不只推最新价，确保 OHLC、成交量和持仓量准确。

WebSocket 只用于加速通知，不作为最终一致性的唯一依据：

- 发现 `eventSeq` 跳号时，客户端重新请求当前页面数据。
- 重连成功后重新访问 `/status`，重新订阅，并增量同步当前 K 线。
- `kline.closed` 到达后以服务端已收盘 K 线覆盖客户端临时 K 线。
- 客户端不得把 `kline.partial` 写入永久状态。

重连采用带抖动的指数退避：1、2、4、8、16、30、60 秒，最大 60 秒；恢复前台时立即尝试一次。

## 三、PC 与 Android 的本地 Rust 后端

### 3.1 保留 Tauri command 接口

前端继续调用现有 `api.getSymbols()`、`getChartKlines()` 等方法。对应 Tauri command 内部从本地 `Services/SQLite` 改为调用 `RemoteApiClient`。

本地 Rust 层包含：

- `RemoteApiClient`：HTTPS 请求、认证和错误映射。
- `RealtimeClient`：WSS、订阅、重连和事件转发。
- `CredentialStore`：Windows DPAPI / Android Keystore。
- `KlineMemoryCache`：K 线 LRU 内存缓存。
- `BackupScheduler`：仅 Windows 启用。
- `ConnectionState`：在线、重连中、认证失效、版本不兼容。
- `AdminClient`：仅 PC 主设备启用，负责配置更新、bridge 重启、服务重启、设备管理和备份。

移除客户端中的：

- SQLite 初始化和迁移。
- `n-core::Services`。
- 天勤 Python sidecar。
- 本地行情刷新、扫描和实时轮询。
- 本地 SMTP 发送。
- 本地数据完整性修复。
- 本地调度状态持久化。

为避免 Android 继续编译整个 SeaORM/邮件/sidecar 依赖，新建轻量 `n-protocol` crate，集中放置 REST DTO、WebSocket 事件、错误类型和共享枚举；服务端与 Tauri 客户端共同依赖，客户端不再依赖完整 `n-core`。

### 3.2 内存 K 线缓存

缓存键：

```text
symbol + timeframe + API schema version + strategy/data version
```

默认：

- 最多缓存 24 个品种/周期组合。
- 每组保留最多 2000 根。
- LRU 淘汰。
- 切回已缓存图表时立即显示，再后台增量刷新。
- 缓存只存在于当前进程，应用重启后消失。
- 服务断开时允许继续查看当前进程已加载数据，并显示“数据截至时间”，但不能编辑或保证实时。
- 不使用本地 SQLite 或 IndexedDB。

现有 `liveBars` 可以在第一阶段继续使用，但数据来源改为 `kline.partial`；服务端完整临时 K 线应覆盖客户端用报价拼出的临时值。

### 3.3 PC 每日数据库备份

仅 Windows PC 主设备执行。

执行规则：

- 应用启动后检查当天是否已有成功备份。
- 运行期间每 6 小时检查一次。
- 若当天尚未成功则立即请求。
- 失败后按 1 分钟、5 分钟、30 分钟、6 小时重试。
- 日期以 `Asia/Shanghai` 为准。
- 每天最多保留一份成功备份。
- 默认保留最近 3 份。
- 保存到 Tauri 应用数据目录的 `backups` 子目录。
- 设置页提供“立即备份”和“打开备份目录”。

服务器不能直接复制正在写入的 `ntrend.db`。备份接口必须：

1. 获取全局备份互斥锁。
2. 使用 SQLite `VACUUM INTO` 或官方在线备份 API生成一致性快照。
3. 对快照执行 `PRAGMA integrity_check`。
4. gzip 压缩。
5. 计算 SHA-256。
6. 通过 HTTPS 流式发送。
7. 删除服务器临时快照。

客户端：

1. 下载到 `.part` 临时文件。
2. 校验响应长度和 SHA-256。
3. 校验成功后原子重命名为 `ntrend-YYYY-MM-DD-HHmmss.sqlite.gz`。
4. 写入同名 `.sha256` 文件。
5. 更新本地最后成功备份日期。
6. 清理超过 3 份的最旧文件。

如果 PC 某天没有启动，该天不会产生历史备份；下次启动只备份当时的最新数据库，不伪造遗漏日期。

自动备份只包含数据库，不包含天勤、SMTP、管理密钥等服务端秘密配置。服务端秘密配置需要单独人工保管。

恢复流程必须写入部署文档：

- 停止 systemd 服务和 Python bridge。
- 保存当前损坏库。
- 解压备份。
- 执行 `PRAGMA integrity_check`。
- 替换数据库文件及对应 WAL/SHM。
- 启动服务并核对 `/status`。
- 严禁服务运行时直接覆盖数据库。

## 四、前端页面改造

### 4.1 全局壳与连接状态

App 顶部或移动端状态栏增加：

- 在线、重连中、离线、认证失效、版本不兼容状态。
- 服务端最后刷新时间、最后扫描时间。
- 当前行情延迟。
- 离线时的固定提示条。
- 所有写按钮在离线状态禁用并说明原因。

PC 保留托盘、多窗口和自定义标题栏。Android 使用单窗口路由，不显示最小化、最大化、关闭、托盘和开机启动设置。

### 4.2 首页

PC 保持现有表格布局。

Android：

- 品种表改为响应式卡片或可控横向表格。
- 分组放入顶部下拉/抽屉。
- 添加品种、移动分组和排序使用触摸菜单。
- 长按替代右键。
- 刷新、扫描等低频操作收纳到更多菜单。
- 行情数据来自 WSS，断线时保留最后值并显示时间。

跨端修改关注、分组和排序后，服务端广播 revision，其他设备自动重载。

### 4.3 K 线页

- 首屏使用内存缓存或请求最近 1200 根。
- 左拖历史时分页加载。
- 收到 `kline.partial` 只更新最后一根。
- 收到 `kline.closed` 后增量同步确认数据。
- 切换品种/周期取消上一请求，避免慢响应覆盖新页面。
- Android 左侧品种列表改为抽屉。
- 信号、画线和详情面板改为底部抽屉。
- 右键操作增加可见按钮或长按入口。
- 保留触摸缩放、拖动和十字线。
- 完整性检查和修复属于服务端管理操作，Android 收纳进高级菜单。

### 4.4 设置页

拆为：

- 服务连接：地址、设备名、绑定、重新认证、连接测试。
- 服务端设置：调度、天勤、邮件、策略、通知阈值；普通设备只读，PC 主设备可编辑。
- 本设备设置：图表、主题、系统通知和页面偏好。
- 设备管理：查看和吊销设备。
- 数据备份：仅 PC 显示。
- 服务状态：数据库、天勤、版本、刷新和扫描时间。
- 服务控制：仅 PC 主设备显示“重启天勤桥接”和“安全重启服务”。

天勤与 SMTP 密码永远只显示“已配置/未配置”，不回显明文。

页面保存配置后逐项显示状态：

- `已立即生效`
- `天勤桥接已重启并连接成功`
- `已保存，需重启服务`
- `验证失败，已恢复旧配置`

当配置要求重启时，页面先保存配置，再单独提示用户执行安全重启，不能把“保存”和“重启”合并成不可撤销的一步。

### 4.5 复盘页

- 所有统计和模型查询改由服务端执行。
- PC 保留宽表。
- Android 使用筛选抽屉、摘要卡片和横向滚动明细表。
- 批注与决策写入成功后等待服务端确认，再更新 UI。
- 跨端收到 `state.changed(signals)` 后刷新当前详情。

### 4.6 通知页

- 通知历史迁至服务端数据库。
- 新通知通过 WSS 推送并落库。
- PC/Android 打开通知页均读取相同历史。
- 清除/已读状态按全局共享处理。
- 首版 Android 应用未运行时不保证系统推送；后台提醒继续依赖现有服务端邮件。
- 后续若需要真正后台推送，再单独接入 FCM。

## 五、阿里云部署

采用：

- `n-headless` 由 systemd 管理，`Restart=always`。
- Rust 服务只监听 `127.0.0.1:8780`。
- Python bridge 只监听 `127.0.0.1:8765`。
- Caddy 对外提供 HTTPS/WSS 并自动续签证书。
- 阿里云安全组只开放 80、443 和受限 SSH。
- 不开放 SQLite、8780、8765。
- DNS 指向阿里云公网 IP。
- Caddy 设置请求体上限、连接超时和基础 IP 限流。
- 服务端认证失败限制为每 IP 每分钟 10 次；普通 API 每设备每分钟 120 次，WebSocket 每设备最多 2 条连接。
- 日志禁止输出令牌、天勤密码、SMTP 密码和完整 Authorization header。
- `/healthz` 只返回存活状态，不返回敏感配置；详细状态必须认证。
- systemd 必须设置 `Restart=always` 或等价策略，确保页面触发安全退出后服务自动恢复。
- 服务启动失败时保留上一个可用配置副本；连续启动失败不得无限覆盖该副本。

正式使用前确认天勤账号及许可允许在个人云服务器运行并向自己的多个设备分发数据。

## 六、迁移与上线顺序

1. 给现有 PC 数据库、阿里云数据库和配置分别做人工归档。
2. 停止旧阿里云无头服务，避免继续写入。
3. 以 PC 当前 `ntrend.db` 作为唯一初始权威库。
4. 将 PC 服务端相关配置迁至阿里云，UI 配置留在 PC。
5. 在副本上执行新数据库迁移。
6. 执行 `PRAGMA integrity_check`，记录各核心表行数。
7. 启动新服务端，仅监听回环地址。
8. 验证天勤、刷新、扫描、邮件、K 线和 WebSocket。
9. 配置 Caddy、域名和证书。
10. 注册 PC 主设备并切换远程模式。
11. 对比 PC 远程结果与旧本地结果：K 线、信号、复盘、分组、画线必须一致。
12. 验证 PC 自动备份及实际恢复流程。
13. 注册 Android 设备并做全部主要页面测试。
14. 稳定运行一周后，将 PC 旧数据库移到只读归档目录；不立即删除。
15. 不再保留本地运行模式相关入口。

## 七、测试与验收

### 服务端

- 两个客户端同时读取和修改分组、排序、画线与批注。
- 重复提交同一 `request_id` 不产生重复数据。
- 天勤断线、恢复和缺口回补。
- 两次调度器启动时第二个进程被拒绝。
- K 线增量、重叠更新、换月和历史修订。
- WebSocket 断线重连和事件序号跳号。
- 旧客户端版本收到明确升级错误。
- 备份生成期间持续写库，恢复后数据库仍通过完整性检查。
- 被吊销设备立即失去 API/WSS 权限。
- 普通设备无法修改服务配置或触发重启。
- PC 主设备修改热配置后无需重启即可生效。
- 天勤新凭据探活失败时旧凭据和旧 bridge 自动恢复。
- 触发安全重启后 systemd 自动恢复，客户端重连并确认配置 revision。

### PC

- 无本地数据库也能完成现有全部主要功能。
- 启动、托盘恢复、多窗口和自动连接。
- 当日仅生成一份成功备份。
- 下载中断不留下可误用的正式备份。
- 30 份轮转正确。
- 服务断开后只显示内存旧数据和最后更新时间，写操作禁用。

### Android

- 首页、K 线、设置、复盘、通知、画线全部可用。
- 横竖屏、返回键、前后台切换。
- 网络从 Wi-Fi 切到蜂窝后自动重连并补数据。
- 令牌不出现在 JS、本地普通配置和日志中。
- 应用被杀后重新启动不会显示旧持久化 K 线。
- 桌面专用插件不会进入 Android 构建。

### 最终验收标准

- PC 和 Android 的品种、分组、排序、画线、批注、决策和通知历史在数秒内同步。
- 同一品种周期在两端显示相同的已收盘 K 线。
- 实时行情和进行中 K 线延迟处于可接受范围。
- 服务端重启后自动恢复调度和天勤连接。
- PC 每日备份可实际恢复，不只是成功下载。
- 服务端秘密信息从未返回客户端。
- 旧 PC 数据完整迁移且有可回退归档。

## 八、关键注意点

- 绝对不能直接复制正在 WAL 写入的 SQLite 主文件作为备份。
- WebSocket 事件可能丢失，重连后必须通过 REST 增量校准。
- 进行中 K 线和已收盘 K 线必须有明确字段，不能混入权威历史。
- 所有时间统一使用服务端时间和明确交易日规则，不能依赖手机本地时钟。
- 服务端只能运行一套刷新与扫描调度器。
- 天勤和 SMTP 凭据不能进入客户端、WebSocket、日志或数据库下载包。
- 不允许通过管理 API 修改监听地址、数据目录、域名、Caddy、systemd、Python 路径或管理密钥，避免远程配置把服务永久锁死。
- 服务重启接口只能触发预定义的优雅退出流程，绝不能接受 shell 命令、文件路径或任意参数。
- 天勤凭据必须先验证后提交；若先覆盖旧凭据再验证，配置错误会导致服务失去自动恢复能力。
- 自动备份依赖 PC 当天运行；PC 不运行就没有该日副本。
- 数据库备份不包含服务端秘密配置，秘密配置必须单独人工保管。
- 客户端不自动重试 mutation，避免网络抖动造成重复操作。
- Android 首版没有 FCM，应用被系统终止后不会收到 WSS 预警。
- 公网 API 只能经 HTTPS/WSS 暴露，Python bridge 和 Rust 内部端口必须保持回环监听。
- 数据迁移验证完成前不得删除 PC 原数据库和旧阿里云数据库。
