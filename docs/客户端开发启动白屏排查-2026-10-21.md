# 客户端开发启动白屏排查（2026-10-21）

## 结论

本次主窗口约 26 秒白屏发生在开发版的本机 HTML 请求阶段。Vite 默认监听整个项目，扫描 Rust 构建目录等非前端文件时，在 Windows 主线程上大量调用 `fs.watch` 注册文件监听，导致已经发出的首页请求迟迟不能得到处理。

已在 `vite.config.ts` 排除构建产物、Rust 源码、回测/诊断产物、运行数据及桥接 flow 缓存等目录。Rust 源码仍由 Tauri 自身监听。没有清除用户浏览器配置、设备认证或交易数据。

## 原始启动证据

- 进程于 02:18:58.945 启动，Rust setup 33 ms，02:18:59.475 已连接远端 WebSocket。
- 从仍在运行的原始页面读取 Navigation Timing，未重载页面：主文档请求在 9.9 ms 发出，25634.4 ms 收到响应头，25635.6 ms 接收完成。
- 等待响应头 **25624.5 ms**，下载 HTML 仅 **1.2 ms**；首次内容绘制在 25660 ms，入口模块执行在约 25939 ms，首页路由就绪在约 26881 ms。
- 这次加载使用 `http://127.0.0.1:5173/`，是 Vite 开发服务。初始加载提示也在 HTML 中，因此 HTML 未到达前无法显示。
- 原窗口使用缓存重验证，但后续空缓存测试同样复现；不能仅根据 `deliveryType=cache` 判断缓存损坏。

## 隔离复现与 CPU 证据

使用同版本 Wry/WebView2、新建隐藏窗口和独立配置目录测试，不连接交易账户。缓存对照仅复制 HTTP/代码缓存，未复制认证、Cookie 或本地存储。

修复前分别复现：缓存副本等待 HTML 响应头 11.38 秒，空配置等待 12.31 秒。浏览器 NetLog 显示缓存读取很快，主要停在发出 HTTP 请求后等待响应头。Vite HTTP 中间件收到请求后的处理分别约 371 / 310 ms，说明大部分等待发生在 Node 尚未调度请求时。

45 秒 CPU 采样中，约 **28.9 秒**累计落在以下栈的原生 `start` 调用：

```text
FSWatcher -> fs.watch -> createFsWatchInstance -> setFsWatchListener
  -> _watchWithNodeFs -> _handleFile / _handleDir -> _addToNodeFs
```

事件循环最大连续延迟达到 11.69 秒。现场 `target` 约 60092 个文件，诊断时 `reports` 约 7943 个文件。原 Vite 配置没有排除这些目录；`.gitignore` 不会自动充当 Vite 文件监听的排除规则。Rust 编译后目录规模和系统负载变化，会使冷启动白屏时长不稳定；热启动快速不能排除此问题。
