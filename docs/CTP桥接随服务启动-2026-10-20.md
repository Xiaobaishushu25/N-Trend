# CTP 桥接随后端启动（2026-10-20）

CTP 与天勤行情桥接一起由 `n-headless` 启动入口管理。后端启动时在后台检查本地8766端口，使用数据源配置中的 Python 解释器运行 `python-bridge/ctp_trader.py --port 8766 --parent-pid <后端PID>`。解释器未配置或不可用时搜索系统 Python，并解析到实际解释器路径，避免 Windows 启动器造成进程归属不一致。账户、柜台地址和交易规则沿用原桥接配置。

CTP 不等待天勤登录成功，也不以柜台可交易状态阻塞后端 HTTP 启动。桥接正在登录、柜台断线或休市时，只要进程还在就继续等待，不反复重启登录；进程确实退出后每5秒检查并恢复。启动失败写入后端日志，前端原有桥接状态会继续显示离线。

启动前校验桥接服务标识及PID：已经运行的 CTP 会被复用；存在未知或无响应的端口监听时不启动第二个交易进程。后端只负责停止自己启动的子进程，不终止被复用的外部桥接。

正常关闭后端时终止并回收拥有的 CTP 子进程；启动失败或后台任务取消时也会清理。Python 额外监测 `--parent-pid`：后端异常退出后，CTP 在约2秒内自行退出，避免留下孤儿进程。Windows 使用只读进程句柄探测存活，不使用可能终止进程的 `os.kill(pid, 0)`。

CTP 子进程输出汇入后端现有日志，认证敏感输出会隐藏。交易执行仍以柜台登录、结算确认及资金/持仓/委托/成交同步就绪为前提，保持原有 `FullAuto` 和10 tick等配置。

本次上线需一次性停止此前独立运行的 CTP，再启动新版后端，让 CTP 成为后端的子进程。之后启动后端即可同时拉起交易桥接，无需另开 CTP 的 tmux 会话。

验证使用不连接柜台的假桥接子进程，覆盖自动启动、柜台未就绪时不重复启动、子进程异常退出后恢复、优雅关闭与启动异常的子进程清理、外部桥接复用及非CTP端口占用。Python回归还覆盖父进程探活和父进程退出处理。
