# P2/P3 多策略实例接入

本实现位于 `codex/multi-strategy-accounts`，沿用实例、独立账户、版本冻结和公共成交状态机。信号来自系统原有 N 结构预警；P2/P3 各自筛选并生成交易意图。默认实例仍采用原 N 策略。

## 模块对应

|方案|信号模块 / 代码版本|退出模块|仓位模块|
|---|---|---|---|
|P2|`n_p2:1`|`p2_fixed_exit_v1`|`candidate_one_lot_v1`|
|P3|`n_p3:1`|`p3_fixed_exit_v1`|`candidate_one_lot_v1`|

P2 固定原 S1；P3 在实际成交后按多头 `min(S1,F+2R)`、空头 `max(S1,F-2R)` 冻结目标。两者固定一手，原结构止损不移动，没有分批兑现、保本或追踪退出。评分门槛 3.0、预警及拟成交风险至少 10 tick、预警摩擦占比不超过 20%、净空间至少覆盖完整止损和费用、预警风险/ATR14 在 `[0.75,2.5]`。

参数和公式以《候选策略实现与模拟测试规格-2026-10-23.md》为依据。费用 20% 和 ATR 只做预警筛选；净空间和实际风险在报单前重新检查。P3 使用真实成交价及结构止损距离计算最终目标，限价检查使用拟报限价进行保守复核。

## 使用入口

1. 更新服务端和客户端后，在交易页“新建”选择 P2 或 P3，绑定独立本地模拟、SimNow 或 CTP 账户。也可在暂停实例的“配置”中载入相应方案。
2. 核对策略参数里的 `fees`、`calendar`，以及账户合约乘数、保证金和手续费。参数使用 JSON，加载预设会替换整个策略参数；保存生成新版本。
3. 新建候选实例采用半自动模式、报单偏移 0 tick、固定一手、最小风险 10 tick，并保持暂停。是否改为全自动由实例执行模式控制。
4. 核对后启用。新实例只接收创建之后产生的新预警；本次代码变更不创建账户、不连接柜台、不自动启用或部署。

P2/P3 的退出与仓位模块必须按表配套，后端会验证；最小风险配置必须为 10 tick。仓位模块始终返回一手，不受“大仓/小仓手数”设置影响。改参数后，旧条件单、委托和持仓继续使用原冻结版本。

## 费用与日历

预设携带 2026-10-22 的参考交易所费用快照，SR 沿用用户指定的往返 2 元覆盖。它不是向柜台实时查询的账户费率，启用前需要核对实际合约与账户费用。支持以大写实际合约编号覆盖品种费率，例如 `PB2611` 优先于 `PB`。

普通费率必须明确提供 `open`、`close_today`、`close_yesterday`，每项包含 `fixed_yuan_per_lot` 和 `notional_rate`；往返采用开仓费加平今/平昨费较大者。也可明确给出 `roundtrip_fixed_yuan_per_lot` 覆盖往返费用；缺字段不会自动当零费用。冻结的筛选费用与本地模拟账本费用分别配置，后者目前仅支持固定元/手代理费用。

参考日历仅覆盖 **2026-07-01 至 2026-10-31**。覆盖外拒绝新增入场，须补齐实际休市窗口并保存新版本。长假前最后日 14:30 停开、14:45 发出退出；周末在品种最后会话收盘前 10 分钟退出，SF/SM 按无夜盘处理。定时器不依赖有新行情才产生退出意图；实际平仓仍需有效盘口及柜台成交回报。休市撤单期间的迟到成交也继续退出。

## 执行与异常

执行版本为 **`candidate-book-v1`**，与历史 OHLC `research-v5` 分开。实际合约的新鲜盘口触发条件单，预警前先碰结构止损即失效；入场至少等待触发后的下一条有效行情。复核需要完整有效买卖价且盘口时间不超过 2 秒，缺行情时等待。

同品种在一个实例内共用槽位，按预警时间、稳定源信号键和条件单编号排序竞争；不同账户独立。明确筛选失败或零成交拒单终止该信号。提交或撤单结果不确定时保留未知敞口及槽位，不把超时视作空仓，不盲目重报；退出完成且订单回报核实后，后续行情才释放机会。

等待按实际观察到的 15 分钟桶计数，超过 12 桶撤回；第 5 个完成持仓桶 MFE 小于 0.5R 退出一次，最多 60 桶。休市不填虚构桶。ATR14 由严格完整的 3 根原始 5 分钟记录合成，简单平均 14 个 TR，午夜 00:00 归入前一时段结束桶。补行情时，第 5 桶判断不使用后续桶的 MFE。

现有行情接口只有秒级时间与买卖价，没有盘口数量或完整逐笔序号。本地模拟采用可成交限价全量撮合，不模拟排队和盘口容量；因此本版本不能称为完整 `paper-tick-v1`，也不能直接沿用历史利润数字。真实报单、成交、条件单及目标均通过公共执行账本保存，重启后恢复冻结版本。

实例快照新增 `strategy_diagnostics`，包括预警过滤理由、冻结输入、拟报单复核及品种槽位。P2/P3 使用相同稳定源信号键，账户对比可以配对两者均已完整平仓的信号，并继续排除存在行情缺口的账户。胜率和交易盈亏因子仍按账户对比原有毛收益口径，净值变化包含已观察费用；配对结果不代表所有被过滤机会的收益差。

## 验证

候选规则测试覆盖费用缺失、ATR 边界与无未来数据、午夜合成、计划和拟成交净空间、多空 P3 目标、固定止损、5/60 桶退出、等待桶与午休、长假/周末及迟到成交。

公共执行测试覆盖下一条行情报单、真实模拟成交、固定一手、版本切换和重启、账户隔离、信号去重、同品种竞争、拒单不重报、撤单未知不释放槽位、P2/P3 完成交易配对。前端测试执行真实表单函数，验证模块配套、参数复制与创建请求；构建执行 TypeScript 检查。

```text
cargo test --offline -p n-core --lib
cargo test --offline -p n-headless
node --test tests/candidateInstances.test.cjs tests/liveTrader.test.cjs tests/simnowLogin.test.cjs

```
