# 休市行情连接提示与主连执行适配修复（2026-10-28）

## 原因与适用范围

“执行行情连接中断，暂停新报单并保留未完成任务”与早先“行情事件不连续”是不同情况。

执行事件请求失败时，共用执行引擎的 `market_unavailable()` 清空盘口并记录连接错误。旧代码只在收到15秒内有效实际合约报价时清除该错误，没有在事件接口恢复响应时清除。因此，启动期间短暂失败或网络恢复后，休市缺乏新报价会让连接中断提示持续显示。该路径属于所有策略共用代码，P2 实盘、六品种及原 N 策略都会受影响，切换策略不能消除它。

六品种另有执行订阅适配问题：`EG0` 等主连代码原先直接输出 `KQ.m@DCE.eg` 对象的报价，合约字段为 `eg`、交易所为 `KQ`，并非可交易实际合约。执行引擎拒绝这种盘口是正确保护；应该修复订阅适配，不能放宽实际合约校验或把主连价格改名后报单。此问题不能用来解释所有 P2 连接报错。

## 修复

1. 执行事件请求成功且无需缺口重新同步时，对所有实例调用 `market_recovered()`。空事件心跳也能清除旧的连接中断提示，与市场是否开盘无关。
2. 该方法仅清除连接错误，不清除真实事件缺口、柜台错误、策略错误、保存错误或已经锁定的风险退出。已有暂停状态不变。
3. 报单仍逐个检查实际合约盘口及15秒时效。恢复连接不生成报价，也不延长旧报价时间。休市旧盘口不会因清除提示而用于开平仓。
4. Python 执行通道解析主连的 `underlying_symbol` 后订阅实际合约，全部价格、买卖盘、涨跌停和时间取自该实际合约 SDK 对象。事件键继续保留策略订阅的 `EG0` 等别名。普通 `/api/quotes` 显示主连的行为不变。
5. 主连换月后，别名切换到新实际合约。新对象尚无数据或主连尚未解析时输出无效盘口，避免继续沿用旧别名盘口；旧实际合约独立订阅仍可服务已有持仓。
6. 策略收到报价回调前即可看到当前别名盘口，覆盖首笔报价及换月场景。
7. HTTP 长轮询返回前再次检查连接状态，避免订阅期间断线却返回成功。
8. 同一实际盘口被主连别名和合约代码同时订阅时，只生成一次事件。增加别名订阅不会制造“下一笔报价”；查询按请求别名返回，实际合约实例仍可按合约字段路由。换月快照移除旧别名关联。
