# 启动白屏与服务端连接排查（2026-10-20）

## 现场证据

- 原日志：Rust setup 15～25 ms；页面内容开始加载（ContentLoading）前等待约 12～24 秒，前端入口执行时间分别为 12.9 / 24.3 秒。主要停顿发生在 WebView 页面加载阶段，不能归因为 Rust 初始化或 Vue 组件渲染。2026-10-21 已核对 Wry 源码：Windows 上 `PageLoadEvent::Started` 对应 ContentLoading，不能把它当作 NavigationStarting。
- 本地 Vite 文档请求约 4 ms。现场启用了 Windows 系统代理和 HTTP_PROXY / HTTPS_PROXY / ALL_PROXY。
- 124.222.199.39:8081 的直连 TCP 建连约 12 ms，但元数据 HTTP 请求 10 秒内无响应；经本机代理访问也无响应。SSH 2222 端口在 banner 阶段超时。
- 用户确认服务器也无法登录，怀疑到期；需要云控制台确认实例状态。尚未恢复服务，不能声称服务端连接已经修复。
- 原客户端 WebSocket 握手没有超时。REST 默认 30 秒且重试一次；设置及状态串行读取导致 dashboard_settings_ready 曾耗时 120 秒，品种加载累计至 180 秒。

## 客户端改动

- 所有 Windows WebView 在本进程中使用 --no-proxy-server；本地 UI 不再依赖系统代理/PAC。Rust REST 同样使用直连，与 WebSocket 保持一致。
- REST 增加 5 秒建连超时和 10 秒读取空闲超时，保留原有总体时限。
- WebSocket 握手限制 8 秒，增加接收心跳超时恢复及握手认证状态处理；保存连接信息时主动中断旧连接/退避，使用新配置重连；清理地址首尾空白及尾斜杠。
- 设置加载去重，远端配置、状态和本地偏好并行读取。本地偏好不等待远端完成。
- App、布局及首页先注册实时事件，再等待远端初始化；历史通知合并时保留期间收到的最新实时提醒。
- 首页按需加载，生产入口 JS 约从 914 KB 降至 591 KB。

先在云控制台确认续费/实例运行状态，再核对公网地址、8081 和 SSH 管理端口。地址发生变化时在客户端设置里更新并保存；新版本会主动重连。保持原设备令牌；不需要因网络超时重新配对或重置数据。
