# 信号形态质量 v1：实现与使用

基点为 `2780aae`，工作分支为 `codex/signal-quality-v1`。实现使用原有 H 盘目录，没有创建工作树。

## 新旧评分的边界

旧 `entry_score`、候选选优、端点、去重、通知门槛、模型输入、准入和仓位保持原有含义。新评分在旧候选已经选定并持久化以后计算，失败只记录诊断，不阻止预警。

独立评价保存在 `signal_quality_evaluations`，不会回写原评分或预测快照。列表批量读取评价；实时冻结优先于历史重算；事件身份、信号代次、特征版本、参数哈希和行情哈希隔离不同结果。

## 规则基线

参数集中于 `crates/n-core/src/quality/quality-rules-v1.json`：

- 形态分 = 趋势25% + A段45% + B段30%。
- 空间分 = `100 × RR / (1 + RR)`，RR只指入场到S1的结构空间。
- 综合质量 = 形态80% + 空间20%。
- 趋势比较S0前背景、A段均线发展、有利侧驻留与反复穿线。
- A段内部排除转折端点，评价路径效率、内部回撤、停滞和重叠争夺；内部不足4根明确标记端点敏感。
- B段比较深度、相对速度、排除预警K后的实体衰减，以及均线离开—返回—破坏—确认过程。
- 实体衰减证据不足取中性分，并明确标记，不视为观察到了衰减。
- 新映射使用连续smoothstep。旧幅度函数1.5 ATR边界跳变作为旧规则诊断保留，没有修改旧公式。

新分为0～100分，不是概率，不对应仓位。比较分布时须先统一刻度，不能仅凭数值跨度较大认定优化有效。

## 因果性与数据完整性

计算只读取已收盘、截至预警的15分钟K线，使用图表同口径SMA20。A/B力量使用ATR20(S1)，均线位置使用当时ATR。S0前最多加载120根、至少需要40根预热。

预警以后的K线、触发、收益和默认 `label_win=0` 均不进入新特征。行情哈希绑定端点与入场几何、tick、实际使用的行情和窗口交易日历；参数另有独立哈希。

历史不足、缺端点、未收盘预警、交易时段缺失、无效OHLC/ATR及窗口换月均返回明确状态。历史重算使用当前快照版本，不能宣称恢复了预警当时尚未保存的原始行情版本。首版不使用手工区域参与打分，也没有把60分钟趋势混同为15分钟MA20。

## 离线重算与报告

在仓库根目录运行，`--out` 必须是工作目录内尚不存在的新目录：

```powershell
cargo run -p n-core --bin signal-quality -- backfill --backup 'C:\Users\Xbss\AppData\Roaming\com.ntrend.app\backups\ntrend-2026-10-29-153437.sqlite.gz' --out research-runs/signal-quality-v1-20261029/my-run
```

- 读取压缩快照和旁边的SHA256文件，验证数据库完整性。
- 在输出目录创建 `source.sqlite` 副本，原始备份只读。
- `backfill` 只向该新副本添加独立评价表，不执行旧库迁移，不修改原事件表。
- `audit`、`report`、`blind-export` 运行同一可复现审计流程，但不向副本添加评价表。
- `--db` 可以替代 `--backup`，输入应为离线快照。不要使用正在写入、尚有WAL的数据库文件。
- `--rules` 允许实验参数文件；与基线不同的参数必须使用新的规则版本。实验参数不会自动成为在线默认规则。
- `--roundtrip-cost-ticks` 默认2.5，是明确记录的研究费用假设；同时比较1/2 tick入场滑点。

主要输出：`manifest.json`、`audit.json`、`four-cases.json`、`summary.json`、`rank-migration.json`、`report.md`、`report.html` 和 `blind-review.html`。

清单记录源文件校验值、基点提交、编译时质量模块源码哈希、规则、参数哈希与执行假设。研究收益使用冻结候选、固定一手、共享5分钟保守执行规则；未知路径、未完成、缺数据和未定价单列。另有按品种、月份、去重叠以及移除T/A/B/空间的分组对照。结果属于历史开发证据。

最新快照的2831条事件中，1884条可完整评价；其余63条历史预热不足、607条窗口缺数据、277条窗口包含换月。2810条能够独立重算旧分，其中12条与落盘有偏差，全部处于缺数据样本；四个案例及完整性通过的1884条旧分均复现一致。偏差证据保存在报告中。

## 已知案例偏差

首版固定规则的综合排序为 `7068 > 7034 > 7086 > 7084`，参考人工排序为 `7068 > 7034 > 7084 > 7086`。

7084的A段推动分高于7086，但其趋势背景和B段分明显较低，合成后仍落后。报告逐项列出这次倒序的贡献差。该偏差保留，作为后续盲评校准的重点，不在识别器中硬编码编号，也没有围绕四例调整初始权重。

首版不以历史收益显著改善作为完成条件，更不据此替换交易评分。

## 界面与开关

图表卡片和复盘列表并排展示旧分、形态分和综合质量，展开可看T/A/B/空间、原始因子、贡献、来源及哈希。

- “新评分”控制前端展示，偏好本地保存。
- “质量排序”只改变展示顺序，默认关闭；关闭新评分后回到原有顺序。
- 没有评价显示“新评分未计算”，数据不足显示具体原因。
- 服务端计算和读取开关为 `settings` 表中的 `signal_quality_enabled`，缺省开启；值为 `false` 或 `0` 时停用独立评价。恢复后不会补造停用期间的实时冻结记录，可另行历史重算。

这些改动需要使用新构建的客户端/服务端才会显示。此次没有部署，也没有替换正在使用的数据库。

## 离线盲评

直接打开输出目录中的 `blind-review.html`。不依赖CDN或外部服务。图形只到预警收盘，隐藏旧分、新分和后续结局，每根K宽度一致，纵坐标以ATR标准化。

先评价形态，再显示交易空间并评价综合条件。允许相近、无法判断和备注；本地保存后下载标签JSON。

默认按四类各50组抽样，总计200组；样本不足如实记录。先按同品种重叠行情的连通区间划分开发/保留集合，再抽样；同一行情簇不会跨集合。已讨论的四例所属簇保留在开发集合。

```powershell
cargo run -p n-core --bin signal-quality -- blind-import --manifest research-runs/signal-quality-v1-20261029/my-run/blind-manifest.json --labels '标签文件路径.json' --out research-runs/signal-quality-v1-20261029/preferences-01
```

导入验证清单字节哈希、显示版本、左右案例及行情哈希、选择值和重复项，输出按开发/保留集合绑定的 `preferences.json`。首版只收集偏好，不训练排序模型。

## 对照解读与补充说明

新版盲评页增加默认收起的“点击展示我的理解”。解读单独存放在 `assistant-notes.json`，不改变原始200组成对任务、案例身份、图形数据或原清单哈希。

- 每组均有趋势、A段、B段与均线、空间及取舍的结构解读草稿；草稿只使用预警前原始指标，不读取旧分、新总分、收益和后续走势。
- 草稿会明确标记“尚未逐图复核”。已经结合图形或结构复核的比较，分别标记来源，不能把自动草稿冒充独立视觉评审。
- 第一组已附结合原始盲评图形复核的比较意见：A段单列略偏左，形态整体及综合条件偏右，具体取舍保留供质疑。
- 第一次展开时记录时间及当时的选择、原因、原始补充说明。展开/收起、显示空间都不会清空当前输入；再次展开不覆盖第一次记录。
- 保存后，最终选择和最终说明与展开前快照一并导出。导入时区分 `reference_viewed`、`no_reference_opened`、`legacy_unrecorded`，这些只描述本页解读的查看状态。
- 旧版已写的说明可从旧页下载标签JSON，然后用新版“导入已有标签”继续；同组记录采用导入文件内容，跨任务或案例哈希不匹配则拒绝导入。

为已有任务附加解读，不必重新计算评分：

```powershell
cargo run -p n-core --bin signal-quality -- annotate --manifest research-runs/signal-quality-v1-20261029/release-fe7b270/blind-manifest.json --audit research-runs/signal-quality-v1-20261029/release-fe7b270/audit.json --review-notes crates/n-core/src/quality/fixtures/reviewed-notes-v1.json --out research-runs/signal-quality-v1-20261029/my-peer-review
```

`--review-notes` 可省略；提供时，复核意见必须绑定同一任务及左右案例/行情哈希。新输出保留原清单字节，另写解读版本与哈希，方便追溯阅读的是哪份理解。带有解读查看记录的标签，应使用同目录下的清单与解读文件导入。

## 20组反馈后的逐个评价

新增离线 `qualify` 流程，版本为 `qualification-evidence-v1` / `qualification-single-v1`。本轮不调整 `quality-rules-v1`、候选、准入或执行规则。

```powershell
cargo run -p n-core --bin signal-quality -- qualify --manifest research-runs/signal-quality-v1-20261029/peer-review-v1/blind-manifest.json --audit research-runs/signal-quality-v1-20261029/release-fe7b270/audit.json --labels 'G:/待处理文件/signal-quality-preferences.json' --out research-runs/signal-quality-v1-20261029/my-qualification
```

打开新目录的 `qualification-review.html`，无需启动应用或服务器。页面嵌入此前20组选择及原话，不把“更喜欢左/右”推断为绝对合格。每个信号分别填写：

- 形态本身：合格、勉强、不合格、无法判断。
- 综合交易条件：同样四档，与形态分别判断。
- 类型：标准回踩N、快速脉冲、整理突破、其他、无法判断。
- 原因与原始补充说明；不完整的选择保存为草稿，不能当成完整标注。

默认给20个未讨论案例，也可切到原40个信号复核。新例从原任务开发集合中按A段贡献集中、B段独立性不足、重叠场景和参考抽样各取最多5例。按全库同品种重叠行情重建连通簇，排除已讨论20组、已知四例及关联簇；新例之间也不重复行情簇。候选池原先经过评分条件抽样，因此这仍是问题定位用的开发材料，不能称作随机市场样本或收益保留验证。

Rust单一诊断实现输出：

- A段顺向实体及收盘新纪录的最大单根/两根贡献、等效贡献根数，完整/内部窗口分别展示，S1反向影线单列。等效根数为 `sum(x)^2 / sum(x^2)`，全零时未知。
- B段截至S2的区间与收盘超出S1范围的距离、首次超出时点和持续根数；预警K单独排除，避免用预警本身制造独立回撤证据。
- 重叠、影线、收盘净位移/总路程和前后半区间比，共同描述整理与争夺；少于4根不推断收敛。端点以外的历史背景另列。

这些只作为诊断证据，没有自动合格阈值或新增评分权重。原盲评载荷没有tick，页面明确缺失，不用默认值补造。纵轴默认固定1 ATR=40像素，并提供全图适配；横向固定每根8像素，标记A/B区间和预警K。解读默认折叠，明确标记草稿；第一次展开保存当时的判断、说明与时间，再次打开或导入较旧的未查看快照不清除已查看状态。

输出包含原字节不变的 `blind-manifest.json`、`assistant-notes.json`，以及绑定原任务和行情哈希的 `qualification-task.json`。下载 `signal-quality-qualifications.json` 同时保留原配对标签、新逐例评价、草稿、解读查看记录。任务哈希覆盖诊断、抽样和展示版本，原配对与新评价各自校验。

导入仍用 `blind-import`，但应使用新目录下的清单，才能同时找到对应的 `qualification-task.json`。未知案例、行情/任务/版本不匹配、重复项或非法选择均拒绝；新评价和草稿分开保留，不训练模型。已讨论的原保留案例及关联簇只用于开发，不再作为未见验证。
