# N-Trend 灾备恢复与服务端运维手册

本文档规定了 N-Trend 服务端化改造后的部署结构、运维操作规范、进程守护机制以及灾难恢复标准作业程序（SOP）。

---

## 一、生产环境部署规范

### 1.1 目录结构与权限

服务端推荐部署在阿里云 Ubuntu 22.04+ LTS 服务器上，固定部署路径为 `/opt/ntrend`：

```text
/opt/ntrend/
├── bin/
│   └── n-headless             # 服务端权威执行文件（Keep二进制名保持一致）
├── data/
│   ├── ntrend.db              # 权威 SQLite 业务数据库
│   ├── ntrend.db-wal          # SQLite WAL 预写日志
│   ├── ntrend.db-shm          # SQLite 共享内存文件
│   ├── ntrend.lock            # 单实例互斥文件锁（包含运行中 PID）
│   ├── secrets.json           # 服务端机密配置文件（权限严格 0600）
│   ├── config.json            # 业务设置配置文件
│   └── logs/                  # 轮转服务日志目录
│       └── ntrend-server.log.YYYY-MM-DD
└── bridge/                    # 天勤 Python Sidecar 脚本目录
```

### 1.2 机密配置 `secrets.json`

云端机密配置（天勤账号密码、SMTP 授权码、管理配对密钥）**严禁**直接暴露给前端客户端，必须单独存放在 `/opt/ntrend/data/secrets.json`，且属主必须为运行服务的专属系统用户（例如 `ntrend`），权限严格设置为 `0600`：

```bash
# 创建配置并锁紧权限
sudo touch /opt/ntrend/data/secrets.json
sudo chmod 0600 /opt/ntrend/data/secrets.json
sudo chown ntrend:ntrend /opt/ntrend/data/secrets.json
```

`secrets.json` 格式如下：

```json
{
  "admin_key": "YOUR_STRONG_RANDOM_ADMIN_KEY_HERE",
  "tq_password": "YOUR_TIANQIN_PASSWORD",
  "smtp_password": "YOUR_SMTP_AUTHORIZATION_CODE"
}
```

> **注意**：
> - `admin_key` 用于新终端客户端首次配对并取得管理员 Token。请使用高强度随机字符串。
> - 客户端发起设置更新时，若留空密码字段，服务端将自动保留 `secrets.json` 中的现有值。

## 二、Systemd 进程守护与日常操作

### 2.1 安装 Systemd 服务

将 `scripts/deploy/ntrend-server.service` 复制到系统的 systemd 目录：

```bash
sudo cp scripts/deploy/ntrend-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable ntrend-server
```

### 2.2 常用服务命令

```bash
# 启动服务
sudo systemctl start ntrend-server

# 查看运行状态与心跳
sudo systemctl status ntrend-server

# 停止服务
sudo systemctl stop ntrend-server

# 重启服务
sudo systemctl restart ntrend-server

# 查看实时运行日志
sudo journalctl -u ntrend-server -f -n 100
```

### 2.3 单实例进程锁排查 (`ntrend.lock`)

服务端在启动时会自动向 `/opt/ntrend/data/ntrend.lock` 写入当前进程 PID。若服务器发生异常掉电或强制 Kill（`kill -9`），下次启动时：
1. `n-headless` 会读取锁文件内的 PID，并检查该 PID 是否仍处于存活状态。
2. 若原进程已不存在（Stale Lock），程序会自动回收该锁并继续正常启动。
3. 若检测到已有运行中的同类实例，程序会安全拒绝启动并报错，防止双实例同时写入 SQLite WAL 导致数据库损坏。

## 三、网络与反向代理部署 (Caddy / Nginx)

服务端默认监听本地 `127.0.0.1:8780`。建议使用 Caddy 作为反向代理并启用自动 HTTPS 与 WSS 支持。

参考 `scripts/deploy/Caddyfile.example`：

```caddy
your-ntrend-server.example.com {
    request_body {
        max_size 500MB
    }

    handle /api/* {
        reverse_proxy 127.0.0.1:8780 {
            header_up Host {host}
            header_up X-Real-IP {remote_host}
            header_up X-Forwarded-For {remote_host}
            header_up X-Forwarded-Proto {scheme}
            transport http {
                response_header_timeout 60s
            }
        }
    }
}
```

## 四、客户端多端配对与权限管理

### 4.1 终端配对流程

1. 启动 PC 或移动端客户端。
2. 打开“设置” -> “服务端连接”。
3. 填入服务端地址（例如 `https://your-ntrend-server.example.com`）。
4. 在“管理密钥快速配对”中输入设备名称（如 `我的办公PC`）及服务端的 `admin_key`。
5. 点击“一键配对并获取令牌”。
6. 客户端将获得由服务端安全派发的专用 Bearer Token，并保存在本地系统凭据管理器中（Windows Credential Manager）。

### 4.2 撤销失窃或废弃设备

主管理员设备可在“设置” -> “设备管理”中查看所有已配对设备（包括设备名称、ID、配对时间、最后活跃时间）。
点击目标设备旁的“撤销授权”，服务端将立即使该设备的 Token 失效，并切断其当前的 WebSocket 连接。

## 五、PC 每日一致性快照与灾难恢复（SOP）

### 5.1 自动快照机制

- Windows PC 主管理员客户端在后台定期运行 `BackupScheduler`。
- 每日首次启动或每 6 小时检查一次。若今日（Asia/Shanghai 时区）尚未备份，则通过 HTTPS 调用服务端的 `/api/v1/admin/database-backup` 接口。
- 服务端在内部获取只读互斥锁后，调用 SQLite `VACUUM INTO` 生成物理一致性快照，验证 `PRAGMA integrity_check` 成功后进行 gzip 压缩并流式传输至 PC。
- PC 客户端保存至本地 `%APPDATA%/ntrend/backups/ntrend-YYYY-MM-DD-HHmmss.sqlite.gz`，并校验 SHA-256 完整性哈希。
- 本地默认保留最近 3 份每日快照，超期文件自动清理。

### 5.2 灾难恢复标准恢复流程 (SOP)

> [!CAUTION]
> **绝对禁止在 `n-headless` 服务端运行期间直接拷贝覆盖 `ntrend.db` 文件！** 否则可能破坏 WAL 索引导致数据永久损毁。

当云端遭遇硬件损坏、文件损毁（`SQLITE_CORRUPT`）或不可逆误操作需要恢复时，请严格按以下步骤操作：

#### 步骤 1：停止云端服务与守护进程
```bash
sudo systemctl stop ntrend-server
```

#### 步骤 2：隔离损坏现场与现有文件
```bash
sudo mkdir -p /opt/ntrend/data/corrupted_archive
sudo mv /opt/ntrend/data/ntrend.db /opt/ntrend/data/corrupted_archive/ntrend.db.$(date +%s)
# 彻底移除可能残留的旧 WAL 和 SHM 文件
sudo rm -f /opt/ntrend/data/ntrend.db-wal /opt/ntrend/data/ntrend.db-shm
```

#### 步骤 3：从 PC 上传最新一致性备份快照
在 PC 客户端“设置” -> “数据库备份”中点击“打开备份目录”，找到最近一份验证通过的快照（例如 `ntrend-2026-09-26-020000.sqlite.gz`），通过 SCP 或 SFTP 上传至云服务器临时目录 `/tmp/`：

```bash
scp ntrend-2026-09-26-020000.sqlite.gz user@your-server-ip:/tmp/
```

#### 步骤 4：解压并验证物理完整性
```bash
# 解压到正式数据库位置
gzip -dc /tmp/ntrend-2026-09-26-020000.sqlite.gz > /opt/ntrend/data/ntrend.db

# 检查 SQLite 数据库完整性（必须输出 "ok"）
sqlite3 /opt/ntrend/data/ntrend.db "PRAGMA integrity_check;"
```
若控制台输出且仅输出 `ok`，说明数据库结构与页面完好无损。

#### 步骤 5：修正所有权与文件权限
```bash
sudo chown -R ntrend:ntrend /opt/ntrend/data
sudo chmod 644 /opt/ntrend/data/ntrend.db
sudo rm -f /tmp/ntrend-2026-09-26-020000.sqlite.gz
```

#### 步骤 6：重新拉起服务并校验健康状态
```bash
sudo systemctl start ntrend-server

# 检查服务健康状态
curl -s http://127.0.0.1:8780/api/v1/status | jq .
```

#### 步骤 7：验证客户端连接与增量同步
打开 PC 客户端，检查顶部标题栏连接标识恢复为绿色“在线”，图表能够正常展示历史 K 线并接收最新实时跳动。
至此，灾难恢复操作完成。
