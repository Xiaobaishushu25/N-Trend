## 鸡蛋报价点值

`precision.rs`将“鸡蛋”及`JD`的点值从5改为10元/报价点。交易单位5吨/手，报价元/500千克，一手包含10个报价单位。连续代码、大小写月份合约和中文品种回退均有测试。

来源：[中银国际期货鸡蛋合约资料](https://www.bocifco.com/newsinfo.aspx?cid=4&id=42071)。点值修正进入共用`effective_multiplier`路径，影响之后计算的货币风险、成交价格盈亏和信号元数据。

P2/P3新信号若仍携带旧JD点值，则拒绝创建计划。已有P2/P3、B5冻结JD计划在入场核验时若仍为5，则以`contract_metadata_mismatch`拒绝新开仓；不把原快照里的5静默改成10。现有持仓的止损和平仓保护继续按原退出路径工作。

历史`realized_pnl_amount`、原始冻结信号、账户权益与柜台账单均未改写。旧记录的更正应作为单独派生对账结果，不能直接把旧账户累计盈亏全部翻倍。

## 后台历史加载

默认账户与独立账户现在共用后台历史加载机制：

1. 后台每5秒检查订阅和数据修订，加载K线及换月记录，不在行情消费者或默认账户委托维护循环内等待全历史数据库读取。
2. 每个账户一个加载任务、容量为1的交接队列；一份更新应用确认后再继续，不并行堆积22份完整历史。
3. 状态变更仍在账户原有执行路径串行应用。独立账户在行情批次之间最多应用一个品种更新；默认账户在维护周期处理一个已就绪更新。
4. 加载结果携带策略修订。初始检查已过期的结果直接丢弃；只有应用成功、结束时修订仍一致的结果才标记为已缓存。失败会重试，逐bar成功游标继续保留。
5. 历史结果就绪可以唤醒独立账户循环；数据库尚未返回时，行情事件和风险定时器仍可运行。后台通道关闭不会导致空转；账户任务结束会取消加载任务。
6. 保留逐Tick顺序、原行情队列上限和`market_gap`风险退出。没有把行情事件缺失改成忽略或自动补造。

读取或应用超过250ms会记录实例、品种或处理耗时；独立实例快照增加：

```text
runtime_diagnostics.quote_queue_batches
runtime_diagnostics.history_errors[]   # symbol/timeframe/error
```

这些变化移除已确认的串行读取阻塞路径，不宣称消灭所有行情缺口。应用策略历史事件时仍可能执行计算及持久化，快照构造也仍有成本；需要部署后根据延迟、队列深度和gap原因继续观察。

## 日历版本与到期诊断

新增`reference-holidays-2026-jul-dec-v2.json`，新建P2/P3参考预设使用`holiday-windows-2026-jul-dec-v2`，覆盖2026-07-01至2026-12-30 15:00。保留原中秋、国庆窗口，不假定尚未配置的2027年边界。2026年休市安排来源：[上期所公告](https://www.shfe.cn/publicnotice/notice/202512/t20251217_829805.html)。

策略诊断及账户流快照提供：

```text
strategy_diagnostics.calendar_health[]
    strategy_id / revision / calendar_version
    coverage_start / coverage_end
    status = ok | expiring | uncovered | invalid
    remaining_seconds / warning_lead_seconds
```

到期前三个自然日（72小时）进入`expiring`；不在覆盖范围为`uncovered`；无效区间为`invalid`。当前策略及仍有待执行任务/持仓的冻结完整K线策略版本均纳入诊断。服务端日志对相同版本、状态和UTC日期去重告警，不在每个行情tick刷屏。

原有未覆盖拒绝开仓逻辑保持。此预警是服务端日志和API诊断，没有创建个人提醒、自动发送消息或新增桌面弹窗。

**已有实例不会因更换预设而自动改日历。**部署后需读取实例当前定义，在保留费用和其他配置的前提下，通过现有策略配置动作启用新日历，生成新策略修订。旧任务仍保持原冻结定义，过期日历不会因升级而静默复活。
