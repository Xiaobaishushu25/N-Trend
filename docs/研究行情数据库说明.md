# 研究行情数据库

数据库 `data/research_market_history.sqlite` 独立于交易应用数据库，仅供研究。`scripts/market_history_store.py` 使用天勤公开 EDB 分钟线和本地天勤历史主力映射快照，不连接交易柜台、不提交订单。当前快照的最新日期保存在 metadata，超过该日期的映射需要另行更新与核对。

映射原始快照位于 `data/research_market_main_mapping.json`，原始来源是项目既有 `tq_continuous_table.response`，快照哈希同时记录在数据库中。更新该快照前应先核对来源和日期，保存旧版以便复现。

覆盖范围是项目研究使用的 22 个品种，并只选择请求区间内曾出现在历史主力映射中的月份合约；对选中的合约请求区间内全部可用分钟数据。这并不覆盖所有非主力月份合约。

## 数据和时间

- `bars` 保存真实月份合约，`period_seconds` 为 60、300、900、3600。`start_ns`、`end_ns` 是 Unix 纳秒时间戳，分别表示实际首根分钟起点和末根分钟终点；展示时转换为 Asia/Shanghai。`bucket_start_ns` 是自然时钟周期桶起点。
- 1 分钟是 EDB 原始 OHLC、成交量和起止持仓量。其他周期由原始分钟线按北京时间自然时钟对齐聚合；遇到分钟缺口则拆分，不跨缺口合并。`constituent_count` 是实际分钟数，`complete=1` 仅表示满周期且连续，并不保证源数据无错或整日完整。部分桶保留并标记 `complete=0`。这个规则尚未与天勤原生 5/15/60 分钟线全面核对，也不等同项目现有以桶末时间标记的行情格式。
- 抽样比对 `DCE.eg2601` 2025-12-03：26 根 5 分钟、8 根 15 分钟完整线的 OHLCV 与天勤回测原生线一致；60 分钟线有差异。10:00 桶本库在 10:15 休市时拆分，第一段为 15 分钟；天勤原生 10:00 线跨休市包含后续数据。两种口径不可混用，回测使用前须自行确认需要哪种小时线。
- `mappings` 是供应商主力合约生效日期及映射快照哈希。交易日与夜盘切换时刻必须结合供应商语义和交易日历额外确认；不要直接把日期当作夜盘换月的准确时间。
- `requests` 记录每个请求、结果行数及响应 SHA-256；请求成功不意味着指定区间全覆盖。没有交易日历完整性审计，也没有逐日历史手续费、保证金、合约乘数审计。研究前需要核对缺口、交易日、换月和实际费用。空结果仍为成功请求，需检查行数。

## 更新

免费接口只支持最近一年的分钟线。示例（日期以请求时免费窗口为准）：

```powershell
python scripts/market_history_store.py --start 2025-11-01 --end 2026-10-27
```

重新执行会跳过相同范围的成功请求；使用 `--force` 可重新请求。不同窗口会以相同合约和时间键更新已有分钟线，并重建该合约的派生周期。重复拉取会覆盖相同时间的数据，目前没有记录同一时间数据变化的历史版本；需要固定回测输入时应先备份数据库快照及其哈希。SQLite 库应使用 SQLite backup API 生成一致性副本。

例如查询鸡蛋某合约完整 15 分钟线：

```sql
SELECT datetime(start_ns / 1000000000, 'unixepoch', '+8 hours') AS beijing_start,
       open, high, low, close, volume, close_oi
FROM bars
WHERE contract = 'DCE.jd2601' AND period_seconds = 900 AND complete = 1
ORDER BY start_ns;
```

三年历史回填已完成并合并：使用标准 TqBacktest 的历史 K 线序列，按 14 天、每组最多四个品种读取，先写入 `data/research_market_backfill.sqlite` 并记录批次。未使用专业版下载接口。53 个预定窗口和 318 个批次成功，隔离库和主库完整性检查通过，合并无重叠冲突；独立相对覆盖检查见 `reports/research_market_relative_coverage_20261028.json`。仍需独立进行交易日历完整性审计和主力切换时刻核对。

窗口定位日期需要晚于日历截止日，因为天勤回测按交易日启动，周五夜盘属于下周交易日。初版定位过早导致窗口末尾漏掉夜盘及最后一分钟；已将初版批次标记为待重跑。修正后抽查 EG 2023-11-10 返回 345 根至 22:59；2025-12-03 至 12-04 返回 690 根，与 EDB 对照全部一致。

查看 `data/research_market_backfill_status.json` 中的 `state`：`collecting` 表示抓取中，`retrying` 表示重试，`aggregating` 表示正在重建派生线，`complete` 表示自动流程完成，`failed` 表示需要处理错误。当前逐批进度见 `data/research_market_backfill_run3.log`，错误日志见 `data/research_market_backfill_run3.err.log`。老的 `reports/market_history_20261028_audit.json` 对应回填前的快照，合并后其数据库哈希不再适用。若进程中断，可重新运行 `python scripts/run_market_backfill.py`；成功批次会跳过。不要同时启动多个回填进程。
