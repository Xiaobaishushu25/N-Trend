# 信号系统 V3 运行与离线迁移

本说明适用于多策略、多账户分支。账户、策略实例和桥接配置见《多策略多账户开发与接入》。

## 正常启动

```powershell
cargo run -p n-headless -- --data-dir ./data --host 0.0.0.0 --port 8081
# 另一个终端启动桌面客户端
npm run tauri dev
```

服务读取指定目录内的数据库、配置和 `secrets.json`，初始化策略实例管理器及后台任务，按配置管理行情桥和独立 CTP 桥。客户端使用 `com.ntrend.app` 身份、正常凭据与系统密钥环；在设置中连接服务端并配对设备。CTP 登录、交易执行模式和账户风控仍由原有配置控制。

启动参数只接受帮助中列出的选项。未知或已移除的参数会在打开数据库、启动桥接之前报错，避免旧启动命令意外进入正常交易流程。

## 旧信号数据库升级

仅在服务已停止且无活动条件单、未对账委托、托管持仓或退出任务的维护窗口运行：

```powershell
python scripts/migrate_signal_v3.py --data-dir <运行数据目录> --archive-dir <独立的新归档目录>
```

脚本不会停止服务、撤单或平仓。它先归档数据库和执行状态，再清理旧信号、预测、模型、模拟结局、信号批注及决策，保留原始行情、合约元数据、换月信息、设备身份、运行配置及真实交易记录。旧交易保存原信号依据，旧影子比较清空，信号 ID 序列不重置。迁移成功后重复运行返回 `already_migrated`。

### 保留原策略和持仓接续升级

需要在休市期间保留旧策略和托管持仓时，可使用显式兼容模式。先通过原服务撤销未入场条件单，确认无活动或未核实委托；获取 CTP `/snapshot`，随后正常停止服务及桥接，再立即运行：

```text
python scripts/migrate_signal_v3.py --data-dir <运行数据目录> --archive-dir <独立新归档目录> --preserve-managed-trades --broker-snapshot <CTP快照JSON>
```

此模式要求快照的持仓同步不超过 30 秒、账户身份一致、柜台与托管持仓逐合约逐方向数量一致，任何 Working、Unknown、CancelPending 或成交回报不完整均拒绝迁移。原 `n_pattern` / `n_exit_v1` 和原执行配置冻结到旧条件单；持仓数量、成本、止损、目标、部分退出状态、历史、未完成退出任务和成交去重记录继续保留，旧信号依据随归档哈希保存。它不会提交全平，也不会自动切成 P2/P3。

新服务会把旧账户接入 `default` 实例，保留原策略继续管理持仓。迁移设置 `execution_signal_not_before`，重建的历史信号不参与新开仓。原始备份保持不变；迁移后若需回退，应先停止新服务并核对最新柜台事实，不能用升级前执行状态直接覆盖已经发生的新成交。

`scripts/prepare_signal_v3.py` 是共用的归档和暂存库准备工具，也可从显式源文件或只读备份接口获取快照。它保留设备与配置；暂存库只用于离线升级，不应另行作为服务启动。输出目录必须全新，原始行情逐行哈希和 SQLite 完整性均须通过核验。

`signal-v3-migration-in-progress` 标记会阻止服务启动。失败后先检查原始归档和恢复结果，再处理标记，不能通过直接删除标记跳过核对。服务检测到尚未迁移的旧信号库时也会拒绝启动。

## 复盘与数据来源

识别算法和人工入场评分继续共享。换月标记进入识别及特征截断，缺失和未完成 K 线不能当作完整行情。实盘持仓以柜台成交回报为准，报价触发不等于实际成交。十五分钟复盘属于较粗粒度回放，路径不明时保留歧义。

预警确认时冻结输入和预测，只使用当时已知信息。历史重建与前瞻来源分开保存，重建库首次正常启动完成重建后恢复前瞻采集。普通离线回放、模型评估和统计工具继续可用，它们不控制服务运行权限或交易执行。

实盘费用、账户收益和四组信号级影子实验各自统计；模拟成本不能作为已经确认的真实手续费。策略版本、实例及账户的统计归属见多账户接入文档。

```powershell
node --test tests/chartReview.test.cjs tests/liveTrader.test.cjs tests/startup.test.cjs tests/signalV3Review.test.cjs
npm run build
```

桥接生命周期测试使用测试进程，不连接真实柜台；串行运行避免进程测试争用。
