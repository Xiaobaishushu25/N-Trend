# 多策略、多账户开发与接入

本次改造保留现有 N 字形算法和四组信号级影子实验，增加策略模块、策略实例、独立账户和公共执行接口。实现位于 `crates/n-core/src/trader/`；正式注册表包含原 N 字形及 P2/P3 候选模块，最小非 N 示例仅在 `instance_tests.rs` 中编译运行。候选接入及费用、日历配置见 [P2/P3 多策略实例接入](P2-P3多策略实例接入.md)。

## 运行关系

一个账户同时对应一个策略实例。同一策略可以复制到多个实盘或模拟账户。新实例默认暂停；启用后接收创建时间之后的新 N 字形信号，不补开历史交易。原账户迁移为固定编号 `default`，旧 `/api/v1/trader/*` 接口始终指向它。

公共行情合并订阅，各账户使用独立任务、委托序号、执行锁和状态目录。CTP 对账必须先通过券商及用户身份验证。默认账户首次成功登录后将身份固定写入 SQLite；以后不能通过更换桥接连接暗中切换账户。

暂停会停止新增入场并撤回仍在执行的入场任务，保护价、持仓退出及已锁定平仓任务继续处理。已有但尚未报单的有效条件单保留，恢复后可以继续；过期单不会恢复。修改执行模式、手数、模块或参数都会生成新版本；已有单据继续使用冻结版本，包括其执行模式。若要立即停止旧单开仓，应使用“暂停新入场”或撤销条件单。

## Rust 策略扩展

`strategy.rs` 提供 `Strategy`、`ExitPolicy`、`SizingPolicy`，模块不能获得 CTP 客户端或执行账本的可写引用。策略按事件接收只读账户、盘口、条件单、持仓及委托信息，返回交易意图；模块可变状态通过 `&mut serde_json::Value` 提供，由执行引擎保存。

新增算法的步骤：

1. 在核心库中新增模块，实现 `Strategy`；如需要，另外实现退出和仓位模块。
2. 在 `StrategyRegistry::default()` 中用稳定的算法编号及代码版本注册工厂；通过 `register_exit`、`register_sizing` 注册所需模块。
3. 重新编译服务端，在交易页创建或复制实例，选择新模块与新账户。

接口示意：

```rust,ignore
impl Strategy for MyStrategy {
    fn subscriptions(&self) -> Vec<MarketSubscription> {
        vec![MarketSubscription {
            symbol: "PB0".into(),
            timeframe: Some("15m".into()),
        }]
    }

    fn on_event(
        &self,
        event: &StrategyEvent,
        context: &StrategyContext<'_>,
        state: &mut serde_json::Value,
    ) -> anyhow::Result<Vec<TradeIntent>> {
        // 使用 context.allow_entries 决定是否提出新的 Open；旧版本仍能退出持仓。
        // 识别机会后返回 Open(EntryPlan)，识别退出后返回 Close。
        // 不在这里进行网络请求、报单、文件写入或耗时回测。
        Ok(vec![])
    }
}
```

`EntryPlan` 用 `Direction::Long/Short` 表达开多/开空，`TradeIntent::Close` 用持仓方向及本实例持仓编号表达平多/平空。入场计划需要稳定信号编号、品种、实际合约、参考价、风险单位、计划手数和产生时间；支持立即触发与突破触发，止损和目标可以缺省。风险单位必须为有限正数，用于现有公共风险距离及滑点计算，不能通过空值绕过。`fixed_v1` 直接采用计划手数。

`signal_id` 在同一实例、同一算法内必须稳定且唯一，重复发出同一信号不会重复新增条件单。策略要把运行状态留在 JSON 状态中；不要依赖工厂创建的对象保存跨事件状态。策略状态、去重游标与输出意图一起提交，避免状态已推进但信号未落盘的中断窗口。确认 K 线游标按版本、品种、周期保存，重放不再次触发策略。订单/成交快照可能重复到达，使用快照中的稳定订单和成交编号处理业务事件。

平仓和修改保护价只能操作本实例、同一冻结版本的持仓。保护价只允许收紧；平仓数量必须为正且不超过托管数量。模块异常会暂停新入场，执行层继续处理已保存的保护计划和退出任务。

`n_pattern`、`n_exit_v1`、`n_score_v1` 封装现有策略；退出和仓位模块同样接收冻结的策略参数。评分门槛、分档、S1 调整、等待 K 线数及无跟进退出不再是外部策略的公共必填字段。`protect_only_v1` 仅执行保存的保护价，适合由策略自己发出退出信号的算法。切换代码版本后要保留仍有条件单、委托或持仓引用的旧版本实现；不存在的版本不会被自动替换成新算法。

`Strategy::entry_constraints` 可选择同品种槽位、下一条行情入场、明确拒绝终止和完整 15 分钟输入；`check_entry` 在触发及报单前复核冻结计划与拟报限价。`ExitPolicy::target_on_fill` 在确认成交后冻结基于成交价的目标。默认实现保持原行为，P2/P3 使用这些接口实现候选规则。原始预警事件附带截至预警时的 ATR14 上下文，候选完整行情事件使用独立的 `candidate15m` 周期，避免与原聚合周期的游标混用。

## 实盘配置

SimNow 账户可直接在客户端创建并登录，流程见下一节。其他 CTP 账户继续在服务端数据目录 `ctp_credentials/` 中准备凭据文件，例如 `account_b.json`，包含 `BrokerID`、`UserID`、`Password`、`AppID`、`AuthCode`、`TdFront`。页面填写引用 `account_b`，以及必须匹配的券商、用户、独立端口；查询接口不返回密码或认证码。

新增账户桥接使用 `--config` 和 `--flow-dir`。缺失或损坏的显式凭据文件会使桥接启动失败，不会退回原账户。各实例的 CTP flow 及报单请求流水分别放在自己的目录中。原默认桥接仍兼容既有启动方式及原 flow 数据；它与新增账户目录隔离。

一个用户身份不能重复配置；一个端口也不能被多个账户占用。可复用已经存在且身份匹配的桥接进程，不会终止非本服务启动的进程。

## 客户端登录 SimNow

交易页的“新建”或“复制到新账户”中选择“SimNow 仿真账户（CTP）”，填写投资者账号、交易密码、交易前置、AppID 和认证码，点击“创建并登录”。服务端自动分配独立桥接端口、保存凭据并启动账户连接，无需手工编辑服务端文件。新实例保持暂停，核对资金、持仓与策略配置后再启用。

已有 SimNow 实例可点击“SimNow 登录 / 重连”。账号固定为绑定账号；密码与认证码留空沿用服务端已保存值。重连只重建当前账户连接并重新核对委托、资金和持仓，不改变策略启用状态。页面分别显示连接、认证、登录、结算确认、资金持仓同步及柜台错误。请求被接受不等于柜台登录成功。

凭据仅写入服务端 `ctp_credentials/`，不写入客户端持久化、实例 SQLite 元数据或查询响应。连接设置查询只返回前置、AppID、账号及“已保存”标记。该目录已加入 Git 忽略规则。Linux 新文件权限为 0600；Windows 沿用服务端数据目录权限。原默认账户兼容 `python-bridge/simnow_config.json`，不再使用源码中的固定账号密码。客户端更新默认账户的登录配置后，后续启动使用服务端保存的独立凭据和 flow 目录。

服务端只重启自己启动的桥接。外部桥接占用端口时会拒绝重连并恢复原凭据，需要先在外部停止该桥接。其他 CTP 账户仍可使用原有服务端凭据引用方式。

SimNow 是通过 CTP 连接的仿真柜台，与本地模拟账本分别标识。前置地址可按 [SimNow 官网](https://www.simnow.com.cn/product.action) 的当前环境信息调整；不单独创建行情连接。

## 模拟账户与对比口径

模拟账户使用独立资金账本，通过同一策略与订单状态机执行，完全没有 HTTP/CTP 发送路径。创建时按实际合约填写乘数、保证金率、开仓费、平昨费和平今费。费用为明确的“元/手”假设，填写零表示明确采用零手续费；未配置的合约拒绝开仓。当前不实现按成交额计费或手续费阶梯，使用对应合约的固定代理费用。

多头使用卖一开、买一平，空头反向；只有新鲜、有效且满足委托限价的盘口才能成交。模型对可成交委托采用全量成交，不模拟柜台排队和盘口容量。资金竞争、保证金释放、开平费用、重启恢复和报单去重均进入账本。

账户对比从部署后的分钟净值样本开始，按用户选择的同一时间区间查询；每个账户显示实际覆盖区间、净值变化、收益率、回撤、完整交易、毛胜率、毛盈亏因子、观察费用和最大保证金。没有足够样本或中间缺样本时显示质量标记，不回填虚构净值。跨分批退出的完整交易先合并，再按最终退出时间计入区间。相同算法和信号编号的完整交易可比较配对毛收益差额；区间内有行情缺口的实例标记质量问题，并保守排除配对比较。

费用差额只覆盖可观察的累计费用变化；不会补估缺失时段。净值变化未调整外部出入金，比较时应避免把入金作为策略收益。现有四组影子实验继续单独展示，不计入模拟或实盘账户净值。

## 存储、接口与恢复

账户和实例目录存放于 SQLite 的 `trader_instance_registry_v1` 设置；分钟净值存放于 `trader_equity` 表。每个实例的配置、版本、条件单、持仓、策略状态及委托热状态位于服务端 `trader_instances/<instance_id>/`。删除实例只移除活动注册关系，磁盘历史保留；有未完成交易的实例禁止删除。新增账户状态损坏时单独禁用该账户并保留原文件，修复后重启恢复，其他账户继续加载。

首次迁移验证原 JSON 并备份到 `legacy-trader-backup/`，复制原配置、执行状态和影子归档到默认实例目录。完成标记写入后不会再次覆盖新目录。原文件保留；迁移、备份核对或执行锁失败会阻止启动交易运行时。回退版本前应停止服务并先备份新目录，不能直接使用迁移前旧状态恢复实盘交易。

客户端与服务端需要同时更新。若远程服务端的 `/api/v1/trader/instances` 返回 404，交易页会显示服务端尚未提供多账户接口的提示，并提供“重新检查”；不会再静默隐藏整个入口。服务端完成更新后可以直接重新检查。

新增 API：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/api/v1/trader/instances` | 列出 / 创建实例，创建支持 `copy_from` |
| GET | `/api/v1/trader/instances/:id/snapshot` | 指定实例快照 |
| GET | `/api/v1/trader/instances/:id/orders` | 指定实例委托分页 |
| POST | `/api/v1/trader/instances/:id/actions` | 显式指定实例的操作 |
| GET | `/api/v1/trader/instances/:id/connection` | 管理员读取脱敏连接设置 |
| POST | `/api/v1/trader/instances/:id/login` | 管理员提交 SimNow 凭据并连接当前账户 |
| GET | `/api/v1/trader/instances/comparison?from=...&to=...` | Unix 秒区间账户对比 |

写操作要求管理员身份。`actions` 的 `action` 值包括 `pause`、`resume`、`delete`、`configure`、`strategy`、`configure_strategy`、`confirm`、`cancel`、`cancel_all`、`close_all`。组合配置使用 `configure_strategy` 同时提交 `strategy` 和 `config`。

新实例推送使用 `trader.instance.delta`、`trader.instance.heartbeat`；每个实例独立维护 `stream_id`、`base_revision`、`revision`。REST 返回对应流的最新基线。页面拒绝其他实例的更新；序列缺口或重启后重新读取基线。旧默认实例继续使用既有推送协议。

验证入口：`cargo test -p n-core --lib trader`、`cargo test -p n-headless`、`cargo test -p n-protocol`、`node --test tests/liveTrader.test.cjs`、`python -m unittest discover -s python-bridge -p test_ctp_trader.py`、`npm run build`。
