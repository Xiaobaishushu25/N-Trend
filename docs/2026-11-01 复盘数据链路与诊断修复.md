# 复盘数据链路与诊断修复

版本：3.0.4。对应《2026-11-01 复盘混合评分与成本诊断排查及修复方案》中的问题。

## 已实现

- `publishedReview`独立store使用reviewQuery/reviewItems/metadata加载已发布摘要，不再从原始事件接口拼接主列表。旧统计继续保留独立入口。
- 摘要携带计划价、模拟开平价、评分失败解释以及MFE/MAE精度与上下界；列表无需逐行请求详情取得卡片基础数据。
- 打开图表传递查询、页游标、所选评分指标、snapshot_id和真实result_version；复用窗口、浏览器路由切换和分页均重新绑定上下文。
- 指定版本时读取不可变结果；只有事件编号时，服务端通过review_current解析已发布版本；不使用profile作为版本，不降级旧详情。
- `useReviewDetail`在请求开始时清空旧详情，校验返回的事件及版本，丢弃过期成功/失败/finally。选中、展开与重试共用这条链路。
- 抽屉先匹配事件和结果版本，再统一使用detail.summary；金额、毛净R、诊断、时间和状态不再分散读取旧摘要。
- v2、v1、原始五分制按所选指标分别显示；无分显示失败状态，不跨版本回退。
- 成本提示检查真实cost.settled、版本、R、乘数及金额覆盖；只有开平价格不能推导成本已结算。
- 计划价和成交价分别显示；未成交显示空成交价；追价深度与执行滑点分别展示，不把缺失滑点显示为零。
- `summary.bars_held`显示为“根交易K（15分钟）”；`detail.holding_count`单独显示为“条（5分钟）”，不按记录条数推断15分钟持仓时长。
- MFE/MAE使用统一格式函数：未知显示“未知”，bounded显示上下界区间，确有数值0才显示0.00R。列表、信号池和抽屉保持一致。
- 缺行情、缺日历、缺参数、待触发、歧义和未成交显示各自状态，不默认已结算；原target与target_1r分开解释。

## 数据与发布

本次修改源码和本地构建，没有访问生产数据库、发起生产重建或更改交易规则。

客户端与服务端必须同时升级到3.0.4；仅更新网页资源不能获得新的桌面命令签名和服务端结果解析。HTTP仍为/api/v2，保持已有严格版本核对。

新增摘要字段对已保存不可变历史详情使用安全默认值。服务端启动时通过实现哈希变化将相关品种重新入复盘队列，原始pattern_events和事件ID保留；后台事务发布后，主列表收到review.changed完成事件刷新。补算尚未完成或失败时显示实际任务状态，不拿旧事件顶替新结果。

截图中的7055/7056/7057不在现有六份本地数据库副本内，不能将隔离测试称为这三条生产数据的实测。部署后仍需用实际已发布版本核对具体评分失败解释与覆盖。

## 回归覆盖

`tests/publishedReview.test.cjs`直接运行当前组件脚本和抽屉模板，覆盖评分量纲、未知/有界/零极值、成本覆盖、未成交价格、详情优先、15m/5m计数、展开加载、请求逆序、过期错误、事件版本不匹配、事件编号入口、空结果、分页快照、过滤变更及窗口上下文切换。

Rust复盘测试同时检查计划价与成交价分离、15分钟计数与5分钟记录数分离、当前已发布版本解析、历史详情不变，以及按已平仓净R筛选盈利/亏损的样本一致性。HTTP测试覆盖省略版本时的发布结果查找语义。

执行命令：

```text
node --test tests/publishedReview.test.cjs tests/reviewBrowser.test.cjs tests/reviewApi.test.cjs tests/chartReview.test.cjs
cargo test -p n-core --lib review:: --offline
cargo test -p n-headless --offline
cargo test -p n-protocol -p n-trend-analyzer --lib --offline
npm run build
```

验证结果：前端相关36项通过；核心复盘21项、服务端34项、协议7项、桌面5项通过；原有显式性能测试1项未运行。`npm run build`（含类型检查）、`cargo check --workspace --offline`及`git diff --check`均通过。

排查目录中的reproduction.json保留修复前17项反例。旧reproduce.cjs是按修复前行为断言的诊断脚本，修复后不再作为通过标准；以上新回归测试验证正确行为。
